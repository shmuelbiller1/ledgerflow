**A defect found in my own J-8 code and fixed this session** (worth recording because it is the kind of
bug that ships silently): `makeStoredZip` encoded every entry with `TextEncoder`, and the year-end
archive pushed each invoice PDF through `new TextDecoder('latin1').decode(bytes)`. Every byte above
`0x7F` would have been replaced with U+FFFD, so the PDFs in the archive would have been **corrupt while
the download still "worked"**. `ZipEntry` now takes text *or* raw bytes, a view inside a larger buffer is
copied to exactly its own range, and an entry with no content is refused. Test: all 256 byte values in a
byte-identical round trip.
