   reads bills. The queue's J-1 assumed a matching import exists for every exported list.

   workspace-wide export dialog), while the queue's J-1 assumed seven lists each export. The real set of
   per-list export buttons is: Bills (Purchases), the ledger grid, query/pivot/trial balance, the report
   screens, and the workspace export dialog (ledger/accounts/customers/vendors/bank/trial balance).
   Chart of accounts, customers, vendors and items export **through** the workspace export dialog as
   `recordExportTable` JSON-CSV, which *does* round-trip through the list import (the J-1 test).
4. **No customer/vendor/item list screen has its own "Export CSV"** either — same dialog.
5. **`toCsv` writes every cell quoted** while `parseCsv` trims unquoted cells; a value with leading or
   trailing spaces inside an export therefore survives (good), but a value with a trailing space typed
   into a spreadsheet does not (unchanged behaviour, documented here so it is not re-litigated).
6. **The import preview's separate problems table caps at 200 rows** while the summary counts every
   row; a 2,000-row file with 400 bad rows shows "400 with problems" and lists 200 (plus the 20 in the
   preview). Worth widening or saying "showing 200".
7. **`Vault` uploads save the file as a data URI inside the row** (existing design, 700 KB cap, the
   `documents` table). Unchanged by me; noted because J-7's list now shows the whole workspace's files,
   so a workspace with many large scans is heavier to load than before. The list query does not select
   `fileUrl` explicitly… it does (whole rows are fetched). **Follow-up worth doing**: read the list with a
   column projection like `queryAttachmentLinkIndexPage` does, so opening Documents does not pull every
