## 4. Fixed on this branch (two truthfulness defects, both in AI #2's lane)

### 4.1 Entity Filings Calendar opened on a stale year and hid failures

- **Was:** `useState<number>(2026)` and `Number(e.target.value) || 2026`. In 2027 the calendar would
  open on **last year's** filings while the heading still said "this year". Separately,
  `entityFilings(...)` was wrapped in `try { … } catch { return [] }`, and the profiles were read
  **outside** that guard — so an unreadable saved label profile (for example a legacy
  `taxProfiles.labels['world:tx'] = null`) either blanked the screen or produced an empty table with
  the words "No due filing for {year} with the current profiles": a **false all-clear** on a filings
  calendar.
- **Now:** the year comes from `getLocalDateISO()` (a typed year is still used exactly as typed);
  reading the profiles is inside the guard; a failure renders
  `role="alert"` "Could not compute the filings for {year} … This is a failure to calculate, **not** an
  all-clear", the "no due filing" sentence is suppressed, and Export CSV is disabled.
- **Tests** (`src/tests/entity-filings-view.test.tsx`, 5/5): opens on the current year; the year
  field falls back to today's year when cleared; a typed year reaches the heading; an unreadable
  profile shows the alert, hides the all-clear and disables the export.

### 4.2 Tax Code Suggestions reported a failure as "no history"

- **Was:** `suggestTaxCode`/`unusualTaxCode` were wrapped in `catch { return null }`, and `null` was
  rendered as "No history for … on or before {date}" and "Not flagged as unusual".
- **Now:** a failure says it could not be calculated — it is never presented as evidence about the
  history — and the "no history"/"not flagged" wording only appears when the calculation succeeded.
- **Tests:** `src/tests/tax-code-suggestions-view.test.tsx` 4/4 (suggestion, unusual code, entity
  fallback, empty state, capped-list provisional banner).

### 4.3 US 1099 Preview — two small truthfulness fixes

- Clearing the tax-year field fell back to a fixed 2026; it now falls back to the current year (a
  typed year is used exactly as typed, including an invalid one, which still reports the error).
- The help text said "(IRS 2026 instructions)" for every year; it now says the thresholds are the
  ones in force for the chosen year. **No threshold, amount or rule changed.**
- **Tests:** `src/tests/us-1099-preview-view.test.tsx` 4/4.

## 4.4 New durable guard: no dead report or settings tab

`Reports.tsx` resolves `REPORT_COMPONENTS[tab.componentName]` and `Settings.tsx` resolves
`SETTINGS_COMPONENTS[tab.componentName]` **with no fallback**, and `componentName` is a plain string,
so a wrong or stale name is a dead tab that types cannot catch. `src/tests/registry-components.test.ts`
(new, 4/4) asserts that every report tab, every settings tab, every main tab and every id resolves,
and that ids are unique inside each registry. Proven to fail: renaming one `componentName` to a typo
makes it report `'us-filing-calendar → UsFilingCalendarReportViewTYPO'`; the registry was restored and
the suite is green.

Current state at this revision: **105 report tabs, 31 settings tabs, 0 unresolved**;
`INTELLIGENCE_TABS_REGISTRY` has one stale `componentName` (`UnifiedIntelligenceCore`, the real screen
is `VIEW_COMPONENTS['intelligence'] → IntelligenceCenter`) — no consumer reads that field, so it is
cosmetic and was left alone rather than renamed in a shared file.

## 5. Reported to AI #1 (money/tax lane — deliberately **not** patched here)

**`src/lib/algorithms/compliance-1099.ts` (`1099_totals`) disagrees with the two 1099 screens for
tax years from 2026.**

- The algorithm defaults its reporting threshold to a flat **$600** (`defaultValue: 600`,
  `const thresholdCents = (inputs['threshold'] ?? 600) * 100`) with no dated row.
- `src/lib/tax/us1099Preview.ts` — used by Reports → US 1099 Preview, Reports → Vendor 1099 Readiness
  and the US Quarter Journey — uses the dated table: **$600 through 2025, $2,000 from 2026**
  (box 2 royalties $10, box 10 attorney $600).
- Reproduction (one vendor marked `is1099`, one paid bill of $1,000 dated 2026, tax year 2026):

```
algorithm rows: [{"id":"v1","vendor":"Acme Consulting","email":"-","amount":"$1,000.00"}]
insight: "Found 1 vendors exceeding the $600 threshold for tax year 2026."
1099 preview screen: forms 0, excluded 1, thresholdCents 200000
```

Same workspace, same year, two different answers. The algorithm is reachable at
Tools → Tax time → "1099-NEC Contractor Totals". Proposed correction (AI #1): read
`threshold1099Cents(year, form, box)` instead of carrying its own default, and keep the input as an
explicit override. Written under Messages in `docs/COORDINATION.md`; not changed here.
