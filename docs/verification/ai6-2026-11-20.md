## What was fixed here

1. **AF6-20261120-04 (Low→Medium) — CSV formula injection behind whitespace (carried AF-010-F5, P3).**
   `sanitizeCsvCell` decided on the first character only, so ` =1+1`, `\u00a0=1+1`, `\u200b=…` and a
   BOM-prefixed formula were exported unguarded from every screen export while `=1+1` was guarded.
   One `looksLikeFormula()` now answers the question for both the writer and `unguardCsvCell`, so an
   export → import round-trip still returns the text unchanged (legacy files included) and a plain
   number such as ` -1,000.00` stays a number. `src/tests/security-csv-formula-injection.test.ts`
   (4 cases, 8 whitespace variants, end-to-end through `toCsv` and `reportCsv`).

2. **AF6-20261120-02 (Medium) — token pages were advertised to crawlers.** `/i/<token>` (invoice),
   `/c/<token>` (portal), `/e/<token>` (estimate), `/invite/<token>` open with no sign-in, and the token
   *is* the credential. All are served the same `index.html`, whose robots meta said `index, follow, …`,
   and `robots.txt` allowed everything — so a link forwarded into a public place could be crawled,
   indexed and snippet-cached. `vercel.json` now sends `X-Robots-Tag: noindex, nofollow, noarchive,
   nosnippet, noimageindex` on those four paths (edge, before any script), `src/lib/privacyRobots.ts`
   sets the same directive on the page meta before the first render, and `public/robots.txt` blocks only
   `/api/` — the token prefixes must stay fetchable or a crawler never reads the `noindex` (Gitar's
   review of this PR was right about that; the first version had both, which cancel). A guard fails if
   `App.tsx` routes a new prefix the rule does not cover, if `robots.txt` disallows a token prefix, or if
   the header stops granting `noindex`. 6 tests.

3. **AF6-20261120-03 (Medium) — a second, unconsented crash reporter that reported nowhere.**
   `index.html` POSTed message + raw stack to `/api/health` on every error; that route has only ever been
   a `GET`, so each error produced a 404 and no record while a stack naming a customer or invoice still
   left the browser — with no consent check, redaction or de-duplication, unlike `errorTracker`. The
   inline script is removed, `APP_INLINE_SCRIPT_HASHES` is now `[]` with the reason written down,
   `vercel.json`'s Report-Only CSP no longer names a hash that matches nothing, and the preflight rule now
   requires the Report-Only `script-src` to drop `'unsafe-inline'` (the tightening it was measuring) with
   a hash required only when the page actually ships an inline script. 3 tests + the CSP suite.

## What was reported, not patched (AI #1's lane)

**AF6-20261120-01 (Medium) — `GET /api/v1/workspaces/:id/export?format=csv`.**
The handler builds the CSV by hand: a `=`-leading description/category/reference reaches Excel as a live
formula (`CWE-1236`), and every amount is written as `/100` + `toFixed(2)` regardless of the currency's
decimals — ¥1,000,000 becomes `10000.00` (100× high) and KWD 12.345 becomes `123.45` (10× low).
Patch: [`audit/agent6-2026-11-20/patches/01-workspace-csv-export-formula-and-currency.patch`](../../audit/agent6-2026-11-20/patches/01-workspace-csv-export-formula-and-currency.patch)
(`git apply --check` clean; `tsc` clean with it applied — verified, then reverted).
Reproduction: `npx tsx audit/agent6-2026-11-20/repro/workspace-csv-export.mjs` prints the bytes before
and after for a formula description, a JPY row and a KWD row.

Also reported for the edge/server half of AF6-20261120-02: `X-Robots-Tag: noindex` on
`/i/*`, `/c/*`, `/e/*`, `/invite/*`.
