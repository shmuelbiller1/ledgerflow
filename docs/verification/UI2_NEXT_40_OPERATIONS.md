## How to verify

- `npx playwright test e2e/visual-regression.spec.ts --grep 'visual operations'`: 160 populated presentations, 390 and 1280, both themes. 390 light and 1280 dark run Hebrew/RTL; the other two run English/LTR. The tests mount production modules with in-memory books and deterministic reads, not mock table components. They enter data, select tabs, prepare packs, assert actual records, run axe, reach the table on Tab, and inspect fifteen CSV downloads per combination. The dedicated invoice/order shell checks remain in the existing browser suites.
- `npx playwright test e2e/operations-boundaries.spec.ts e2e/w6-order-deposit-part-invoices.spec.ts`: open two orders with different edit permissions; hide a column, filter, sort, print, and submit a two-unit line at $3.50 to the correct order. Check the actual receipt and payslip; cancel a bank-account draft; count three units at $7.50 against five; verify pick-slip, partial-read and invoice boundaries. No real bank files or live financial commands are used.
- `LF_OPERATION_EVIDENCE=/path/out` with the visual test also records each viewport and table/card matrix. Original and migrated body/footer cells were compared **in order**, not just counted. Of 3,796 cell comparisons, 3,788 are byte-identical; the other eight are the same February 3 and February 12 dates in the reader’s chosen display format on the data-quality and dunning reports. The headerless invoice draft gained screen-reader column names. The source CSV stays machine-readable. Captions/column labels are not part of this cell count.
- `npx tsx scripts/codemod-row-table.ts --files`, `computeQualityMetrics()` and `src/tests/raw-table-decisions.test.ts` independently measure the files still left. The screenshots are not the ratchet. Use a migrated test Postgres for DB and RLS tests; use a production build for the bundle budget.
