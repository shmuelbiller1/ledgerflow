### Writer contract (verified by `src/tests/uniform-structure-writer.test.ts`, 22/22)

- Line widths pinned to the SHAAM field tables: A000 466, A100 95, B100 317, B110 376, C100 445, D110 339, D120 222, M100 294, Z900 110 — asserted per line, every test.
- Record numbers run 1…12 across the fixture file (A100 first, Z900 last); A000 field 1002 = Z900 field 1155 = total records.
- INI = A000 line + one 19-char summary per record type (`code.padEnd(4)+count.padStart(15,'0')`), counts equal to the records actually in BKMVDATA — matches SHAAM's `ini-text.test.ts` contract (minimal file = A000 + A100 + Z900).
- Amounts: sign + 14-digit agorot (fixture 1180000 → `+00000001180000`); quantity sign + 12+4 (`+0000000000100000` for 10); VAT rate `1800` (18% at V99(2)); M100 quantities at X9(9)V99.
- Dates: real calendar days only (arithmetic leap rule — no `Date.UTC`, the quality ratchet counts those); `20250230` → named problem.
- Encoding: ISO-8859-8-i (A000 1029 = 1); `שלום` → `F9 EC E5 ED` (final mem 0xED); ASCII passthrough; gershayim/dashes substituted with a counted note; unmappable (`é`, `€`, emoji) → blocking problem, never a silent byte.
- Refusals (block `canDownload`): missing/short tax ID, bad process date/time, unbalanced journal, duplicate account key, journal account without B110, missing/oversized document number (UUIDs > 20 chars will block — real document numbers required), amount/quantity overflow, unmappable characters, required-field gaps. Overflow keeps the record at exactly its layout width with the field blanked — never truncated.
- `readyForFiling: false` always; `notes` list the zeros written for unrecorded software 1006/1009, substitutions, and the simulator disclaimer.

### Assembler contract (`src/tests/uniform-books-input.test.ts`, 8/8)

- Only `isPostable` entries dated in the chosen year become B100 lines, using the books' own `lineAmount` figures (no conversion); per-account debit/credit totals feed B110.
- Document mapping: invoice → 305, bill → 500, credit note → 330, vendor credit → 410; draft/void statuses counted in `skipped` with a note, never written; line-less documents get one quantity-1 line so totals are exact.
- Posted payments with allocations → D120 under their document (cash 1, check 2, card 3, bank transfer 4, other 9); unapplied posted payments counted + noted; draft payments ignored entirely.
- M100 deliberately empty: opening/in/out totals are not carried by the item records and are not invented — the gap is a visible note.
- Dealer number (A000 1003) = IL `vat` registration, nine digits (`ilDealerNumber`, same rule as `ilWithholdingFileNo`).
