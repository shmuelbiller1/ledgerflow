## 2. A-231 — the last six UTC dates → 0

The metric (`scripts/quality-metrics.ts`) counts lines matching
`getUTC(Date|Month|FullYear|Hours|Minutes|Seconds|Day)` / `Date.UTC` / `toUTCString`; it does **not**
count `toISOString().slice(0, 10)`. At this branch `utcDateCount === 6` and all six are in AI #1's
lane:

- `src/server/http/serverKit.ts:37–39`
- `src/server/routes/transactions/helpers.ts:25–27`

(each builds `YYYY-MM-DD` from `getUTCFullYear`/`getUTCMonth`/`getUTCDate`). **0 outside
`src/server/**`.**

Two real, reachable "today" values outside that lane were checked:

- **Fixed here:** the printed page header in `src/core/layout/RootLayout.tsx` wrote
  `new Date().toISOString().slice(0, 10)` — the device's UTC day on every printout. It now uses the
  same workspace-day helper as the rest of the app, `getLocalDateISO()` (`src/lib/utils.ts`), which
  reads the open workspace's own time zone. Display only; no posting, no stored date.
- **Handed to AI #1 (not patched):** `src/services/ledgerPost/postingCore.ts:75` falls back to
  `new Date().toISOString().slice(0, 10)` for "today" when the posting context has no date. That is
  posting code.

The remaining 18 `toISOString().slice(0, 10)` sites outside `src/server/` are round-trip validators
of an explicit `YYYY-MM-DD` string (`new Date(\`${value}T00:00:00Z\`).toISOString().slice(0,10) ===
value`): they compare a UTC-built instant to itself and cannot drift. They are listed in the audit
list rather than changed, because rewriting them would be churn with no behaviour change.

## 6. A-235 — empty, loading and error states on the ten busiest screens (done)

**One shared pattern, one source of words, one retry:**

- `src/lib/ledgerCollections.ts` — `COLLECTION_LABELS` and `collectionList()` moved here so the
  status bar and the new notice say the same thing ("entries", "invoices", "bill and vendors" read
  the same everywhere). `DataStatusBar.tsx` now imports them instead of keeping a private copy.
- `src/hooks/useScreenDataHealth.ts` — for the collections a screen needs, returns `loadingKeys`,
  `failedKeys`, the store's own message, `ready`, and `retry()` which asks the store for every failed
  collection again. Demo mode never reports a failure (the same rule as `useLedgerCollections`).
- `src/components/ui/ScreenDataNotice.tsx` — `role="alert"`, one sentence naming what failed, the
  reason when the store has one, "Anything below may be empty or out of date", and one `Try again`
  button (44 px). Renders nothing when nothing failed.
- Wired into **eight** screens that had no retry surface: Sales, Purchases, Reconciliation,
  Profit and loss, Balance sheet, Trial balance, Taxes, Settings. **Dashboard** and **Banking** already
  had a load-failure state with its own working "Try again" (and their own tests); they are counted
  in the ten and left as they are, so their existing tests keep their exact expectations.

**Tests:** `src/tests/screen-data-states.test.tsx` — **11/11 pass** (`node --test`), one per screen
plus one for a dropped connection:

| Case | Asserts |
|---|---|
| Dashboard | `Could not load your books` + retry clears `failed.transactions` |
| Sales | `Couldn't load customers and invoices`, reason shown, retry clears both, notice disappears |
| Purchases | `Couldn't load bills and vendors`, retry clears both |
| Banking | its own panel `we couldn't load your bank accounts`, its `Try again` clears `failed.accounts` |
| Reconcile | `Couldn't load bank lines`, retry clears it |
| Profit and loss | `Couldn't load entries for this report`, retry clears it |
| Balance sheet | `Couldn't load accounts for this report`, retry clears it |
| Trial balance | `Couldn't load journal entries`, retry clears it |
| Taxes | `Couldn't load tax codes`, retry clears it |
| Settings | `Couldn't load accounts for settings that read your books`, retry clears it |
| dropped connection | `markFailed` with a `TypeError('Failed to fetch')` records a `transient` retry plan with ≥1 attempt, and the screen says `Couldn't load invoices` |

The network is failed the way the app records it (`useDataNeedsStore.markFailed`, called by
