## D-47 design and failure behavior

- A SHA-256 key derived from `[uid, workspaceId]` selects a nested record under `reportPreferences` in the user's existing private `users` profile. Each record contains only normalized recent report IDs, pinned internal pages, its user/workspace identity, and `updatedAt`.
- The write is a dotted `updateDoc` (`reportPreferences.<scopeKey>`). Two workspace records therefore update independently instead of replacing a whole profile map. The existing own-user RLS, personal-data export, and account deletion already cover the profile; no new personal-data table or reserved `src/server/` change was introduced.
- The migration allowlists the top-level `reportPreferences` profile field and adds `users` to `supabase_realtime` when that publication exists, so another device's write triggers a fresh profile read rather than waiting for a later reload. SQL tests cover two independent nested writes, preservation of unrelated notification preferences, own-user access, cross-user denial, the existing top-level field allowlist, and publication membership.
- Remote and local values are validated against the current report/page registries. Recent reports remain unique and capped at five; pins remain unique and capped at nine. A record whose embedded identity does not match the requested scope is ignored.
- The scoped local copy is read first. Only guest mode inherits the old device-global D-44/I-21 copy; an authenticated user/workspace never inherits another signed-in user's unscoped values. A remote snapshot replaces a clean device copy; an unsynced local edit survives reload and is saved instead. A remote answer during a local write cannot clobber that write. Switching books unsubscribes the old scope and loads the new scope.
- Saves are debounced and serialized. A failed save leaves a pending local copy and an honest error; another edit or reconnect retries. Blocked local storage leaves navigation usable and displays that no device copy could be kept. The picker distinguishes device-only, loading, saving, synced, and failed states.
