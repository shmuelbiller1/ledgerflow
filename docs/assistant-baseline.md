## Part 3 — remembered decisions (before / after)

- **Before:** every proposed step started from scratch. A payee the person had already coded to the
  same account many times was proposed with no account, and the model had to work it out again.
- **After:** each accepted or rejected sandbox step updates `assistant."rememberedDecisions"` in the
  same transaction, per workspace, keyed by command + payee/vendor/customer + field (account, cash
  account, tax code, class). A choice is offered only at ≥95% over ≥5 cases, labelled "from your
  earlier choice" with its case count (the assistant read tool `remembered_choices`, `POST /sandboxes/:id/tools/remembered_choices`). It is never applied
  to the step and never auto-accepted. A member lists it (`GET /sandboxes/remembered`) and forgets one or all with the registered command `assistant.forgetremembered`.
  Only ids and codes are stored; no amounts, memos or other book text. The assistant's database role
  has no access.
- **Measured effect:** none yet. It needs real accept history; the turn metric will show it as fewer
  tool calls on steps with a remembered account.

## Parts 4–7 — what moved (summary; the tables below are regenerated by `--write`)

Each table is a replay of the same 30 questions, asked twice. The first three switch one part back off, and the last is today. What moved:

- **Part 4 (cache).** On the second pass, 8 of the 9 code-answered questions come from the cache: 10 tool calls are served without reading the books again. The ninth ("List my last five payments") uses `list_records`, a cheap read that is deliberately not cached. Model turns send the same system prompt and tools byte for byte (`assistant/systemPrompt.generated.ts`, `src/tests/commands-generated.test.ts`), so the provider's prompt cache can serve them. That cuts the fixed prompt's input cost by about 90% at Google's cached price. The version check itself is measured. On one workspace with 200,000 audit rows and 5,000 customers it took 72 ms when it hashed every table. Scoped to what a read can use, it takes 13 ms for a report and 6–9 ms for a search (the audit log is excluded; a search checks only its own collections).
- **Part 5 (tools by area).** Model turns are offered a median of 10 tools instead of 25, and the fixed prompt drops from 12,697 to 2,133 estimated tokens per turn (−83%). `find_command` reaches all 108 draftable commands (`src/tests/assistant-speed-sbx2.test.ts`).
- **Part 6 (two models).** 13 of 21 model turns go to the simple model and 8 to the strong one, with the reason logged on each turn. The estimated input cost of the fixed prompt on the first call of the 21 model turns falls from 8.0 to 4.2 cents, and to 0.42 cents when the prompt cache serves it. This is an estimate from list prices, labelled as such; measured tokens, time and cost need a model key (`docs/FOR_YOU.md`).
- **Part 7 (plan meter)** moves no replay number, as the spec allows. It is covered by the route tests: a 402 at the limit, code answers still working, and no cheaper model used instead.
- **Not changed:** 9 of 18 book questions are answered by code per pass, as after Part 2 (18 of 36 over both passes). None of the questions that need the model is answered without it.
